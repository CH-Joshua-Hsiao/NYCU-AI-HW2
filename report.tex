\section{Introduction and Motivation}
In this project, we implement SimCLR, a popular Self-Supervised Learning (SSL) method. Usually, training deep learning models requires a lot of labeled data, which is hard to get. SimCLR tries to solve this by learning features from unlabeled images.

Our main goals are to answer these questions:
\begin{enumerate}
    \item How close can an SSL model get to a fully supervised model on CIFAR-10?
    \item How well do the features learned by SSL transfer to a different dataset like CIFAR-100?
    \item How do hyperparameters like temperature, batch size, and the projector head affect the training?
\end{enumerate}

\section{Methods}
The project was built using PyTorch. \textit{Note: AI tools like Gemini were used to help with code structure and LaTeX formatting.}

\subsection{Dataset and Data Augmentation}
We used the CIFAR-10 dataset ($32\times32$ RGB images, 10 classes). In SimCLR, data augmentation is very important. We apply two random augmentations to each image to create a positive pair. Our augmentation pipeline includes:
\begin{itemize}
    \item \textbf{Random Resized Cropping}: Helps the model recognize objects from different sizes and parts.
    \item \textbf{Random Horizontal Flipping}: Helps with spatial invariance.
    \item \textbf{Color Jittering (80\%) \& Grayscale (20\%)}: This is a critical step. If we don't use color augmentations, the network might just look at the color distribution as a "shortcut" to match the images, instead of learning the actual shape of the objects.
\end{itemize}

\subsection{Model Architecture}
We modified the standard ResNet-18 to work with the small $32\times32$ CIFAR images. We changed the first $7\times7$ conv layer to a $3\times3$ conv layer and removed the first max pooling layer. This prevents the image from shrinking too fast. The final classification layer was replaced with a global average pooling layer, giving a 512-dimensional output vector $h$.

\subsection{Projector Head}
We added a 2-layer MLP (linear $\rightarrow$ BatchNorm $\rightarrow$ ReLU $\rightarrow$ linear) on top of the backbone. This head maps the 512-dimensional vector $h$ into a smaller 128-dimensional vector $z$.

\subsection{Loss Function}
We used the NT-Xent (Normalized Temperature-scaled Cross Entropy) loss. It calculates the cosine similarity between the positive pair and scales it by a temperature parameter ($\tau=0.5$). It tries to pull the positive pair together while pushing all other negative samples in the batch away.

\section{Experiments and Results}
We trained the SimCLR baseline for 200 epochs with a batch size of 256. For evaluation (Linear Probing), we froze the backbone and trained a simple linear classifier for 100 epochs.

\subsection{Ablation Studies}

\textbf{1. Temperature ($\tau$):}
\begin{figure}[H]
    \centering
    \includegraphics[width=0.9\textwidth]{ablation_temperature.png}
    \caption{Training with different temperature values.}
\end{figure}
\textit{Are the changes of the two learning curves consistent?} \\
No. When using $\tau=0.1$, the loss drops very low, but the final kNN accuracy (82.39\%) is actually worse than the baseline $\tau=0.5$ (83.10\%). A small temperature makes the model overconfident on a few easy negative samples, so the loss looks good but the features are not actually better. High temperature ($\tau=5.0$) makes everything too uniform, so both loss and accuracy get worse.

\textbf{2. Batch Size:}
\begin{figure}[H]
    \centering
    \includegraphics[width=0.9\textwidth]{ablation_batch_size.png}
    \caption{Training with different batch sizes.}
\end{figure}
Surprisingly, the accuracy stayed very stable (around 82-83\%) even when we dropped the batch size to 32. This is likely because CIFAR-10 is a simple dataset with only 10 classes. Even a small batch size provides enough different negative samples for the model to learn good features.

\textbf{3. Projector Head:}
\begin{figure}[H]
    \centering
    \includegraphics[width=0.75\textwidth]{ablation_projector.png}
    \caption{Testing the impact of the projector head.}
\end{figure}
If we train without the projector (calculate loss directly on the 512-dim output), accuracy drops to 80.94\%. If we train with the projector but evaluate on its 128-dim output instead of the 512-dim output, accuracy drops to 78.67\%. This shows the projector acts as an "augmentation absorber." It throws away details to match the augmented images, leaving the useful features safe inside the 512-dim encoder output.

\section{Discussion}

\subsection{Are the results and observed behaviors what you expect?}
My initial expectation, based on the theoretical concepts of contrastive learning, was that SimCLR would be able to learn strong, useful features entirely without labels. That proved true, as my model reached an impressive 82.82\% accuracy just by looking at augmented images. However, there were a few things that really surprised me during the experiments. 

First, when I compared the Supervised Learning (SL) model with SSL, I expected SSL to be close. But seeing SL hit 92.26\% on CIFAR-10 made me realize just how incredibly powerful direct label supervision is when testing on the exact same dataset. Second, the kNN monitor we implemented was a lifesaver. I was watching the training logs, and sometimes the contrastive loss would jump around or look weird, but the kNN accuracy kept steadily climbing. It was really cool to see the representation quality improve in real-time.

But the biggest surprise was the batch size experiment. All the literature and papers say SimCLR needs massive batch sizes (like 4096 or 8192) to get enough negative samples. When I ran the code with a batch size of 32, I honestly expected the model to fail completely and learn nothing. I was genuinely surprised to see that dropping the batch size down to 32 barely hurt the performance at all (still getting around 82\%). After thinking about it, I realized this makes perfect sense: CIFAR-10 is a very simple dataset with only 10 classes. Even in a tiny batch of 32, the model is already seeing examples from almost all 10 categories, providing enough negative variety to learn good boundaries.

\subsection{Factors affecting the results, including dataset characteristics}
The most critical factor affecting my results, especially in the transfer learning phase, was the dataset itself. When I took the models trained on CIFAR-10 and tested them on CIFAR-100, the SL model's accuracy crashed to 43.38\%, while the SSL model did slightly better at 45.43\%. 

This observation really made me understand the concept of "overfitting to a domain." The SL model basically memorized the 10 specific classes of CIFAR-10. For example, it might have learned to look at green backgrounds to classify frogs, completely ignoring the shape of the frog itself. When moved to CIFAR-100, those "shortcuts" became useless. SSL, on the other hand, didn't have any labels to rely on. It was forced to look at the actual shapes, edges, and textures of every single image to tell them apart from their augmented twins. This resulted in more robust, general features. 

However, 45.43\% is still a failing grade in terms of absolute accuracy. I believe the main limiting factor here is that CIFAR-10 lacks sheer visual diversity. It only has 50,000 tiny, blurry images across 10 basic categories. No matter how perfectly the contrastive loss is optimized, the model cannot magically learn semantic concepts or shapes it has never seen. To build a true "foundation model," SSL clearly needs to be trained on massive, diverse datasets like ImageNet.

\subsection{Experiments I would do if there were more time available}
If I had more time and didn't have to worry about GPU limits, I would love to deeply explore the data augmentations. I would run experiments where I completely turn off color jittering to see if the network really does "cheat" by using color histograms, as the original paper warns. I would also like to try adding completely new augmentations, like Gaussian Blur or Random Rotation, to see if making the task harder helps or hurts the learning process.

I would also love to try training the SimCLR backbone for a much longer time, like 1000 or 2000 epochs. Supervised learning plateaus pretty quickly, but SSL methods are notoriously slow to converge. Since SSL doesn't have labels to overfit to, I am curious if SimCLR could eventually close the 10\% gap with the SL model on CIFAR-10 if just given enough time to train. Finally, I would experiment with the projector head's output size (changing it from 128 to 64 or 256) to see exactly how much compression is ideal before doing the contrastive loss.

\subsection{What I learned and remaining questions}
Through this project, I learned how tricky it is to train self-supervised models compared to standard classification. Getting the hyperparameters right is critical. For example, I learned that raw training loss can be a terrible and deceptive metric in SSL. My temperature ablation ($\tau=0.1$) showed a beautiful, low loss curve, but the actual kNN accuracy was worse than the baseline. This taught me the practical importance of constantly monitoring the representation space with a downstream metric (like kNN) instead of just blindly trusting the loss function. I also clearly saw how SL builds "brittle" task-specific features while SSL builds "general" features.

I have two main remaining questions. First, what is the theoretical limit of contrastive learning on small datasets? Even with infinite training time and perfect hyperparameter tuning, is it mathematically possible for an SSL model to completely match an SL model on CIFAR-10 without any human-provided labels? Second, I wonder how few labeled images we actually need to beat the SL model. It would be really interesting to take my pre-trained SSL backbone and fine-tune it with just 100 or 500 labeled images to see if it outperforms the model trained from scratch with 50,000 labels.
